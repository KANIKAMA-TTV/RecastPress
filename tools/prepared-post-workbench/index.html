ローカル入力作成

公開用 JSON 入力ワークベンチ

記事の文字を整え、CLI に渡す入力ファイルを作成します。

記事データをこのタブで編集し、JSON へ書き出します。 入力は送信・自動保存されません。タブを閉じる前に書き出してください。最終受理は CLI で確認します。
OPEN / JSON

保存した JSON を開く

schema 1・最大 8 MiB。ファイルはこのタブだけで読み込みます。確認後に適用するまで、編集中の内容を保持します。

ファイルは未選択です。

    適用すると現在の記事一覧をすべて置き換えます。残したい内容は先に JSON へ書き出してください。読込み前の一覧へ戻す操作はありません。

    01 / POSTS

    記事一覧

      最後の 1 件は削除できません。文字の編集は入力欄の通常の Undo を使えます。

      02 / EDIT

      記事の入力

      入力値をそのまま保持

      単一の / で始まる明示的な値。最大 8,192 UTF-8 bytes。自動で slug は作成しません。

      HTML・script・ショートコード風の文字も、そのままの文字として扱います。

      03 / TEXT PREVIEW

      文字プレビュー

      入力した文字の表示を確認します。タグも文字として表示します。

      
          
      
        
      
      
      
    
      

    
      
      
      04 / EXPORT
      JSON 入力を書き出す
      schema 1・全記事を一覧順に出力。内部 ID は含みません。
      
      
      prepared-posts-input.json
      
      
      
      
        
      
        公開用の固定サンプルを読み込みました。
        
    
        

    
        
      
        05 / PACKAGE
        公開用ファイルを ZIP にまとめる
        
        
        現在の記事を、文字として表示する固定レイアウトへ変換します。HTML 風の入力も文字のまま扱います。ZIP には bundle.json と receipt.json だけを含めます。
        
      
        
      
        
        
        
        
        prepared-post-package.zip
        
      
        
      
        現在の内容で ZIP を準備してください。入力 JSON の書出しも引き続き利用できます。
        
      
        
        
        保存した ZIP を解凍し、リポジトリのルートで次を実行します。path は解凍先に合わせてください。receipt はファイルの組合せを照合するためのもので、公開の承認や署名ではありません。
        
        
        cargo run -p recastpress-server --bin recastpress -- check-package target/prepared-post-package/bundle.json target/prepared-post-package/receipt.json
        
        
        ZIP の準備やダウンロード開始は、保存完了・CLI 受理・公開を意味しません。入力は送信されません。
        
      
        
    
        

    
        
      NEXT / CLI
        CLI で最終受理を確認
        
      
        リポジトリのルートで実行します。出力先は、まだ存在しないディレクトリを指定してください。
        
      
        cargo run -p recastpress-server --bin recastpress -- prepare-post-package prepared-posts-input.json target/prepared-post-package
        
      
        ダウンロード開始は保存完了や CLI 受理を意味しません。ブラウザーの保存先・ファイル名を確認してください。HTML escape 後の出力量など、最終的な bundle の受理は CLI が判定します。
