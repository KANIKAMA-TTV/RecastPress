# v0.5実装の進捗

2026-11-01。設計は`design/v0.5`、実装は`dev/v0.5`で進める。旧[開発記録](development.ja.md)と既存仕様書は履歴のまま保持する。新設計の入口は[設計v0.5](proposals/2026-11-01-rust-wp-server/README.ja.md)。0.5.0は開発開始版であり、P0受入完了を意味しない。

## 完了した独立実験

| 範囲 | 観測 | 残る境界 |
| --- | --- | --- |
| Rust直接実行の仕組み | [PHP 8.2.6 WASIp1](../experiments/php-wasi-host-probe/README.ja.md)で41項目、失敗後の正常要求11回、並列4要求、CGI解析9テスト | 古いfixture。実DB・通常WP bootstrap・製品runtimeではない |
| PHP 8.5.12候補の実物 | [成果物検査](../experiments/php-runtime-candidate-probe/README.ja.md)でZIP/Wasmハッシュ、標準EH、WASIX ABI、shared imported memoryを確認 | 構造検査自体はengine検証・PHP実行ではない |
| 通常PHPの基準 | 同実験で基本値・例外・Fiber・WPフック・通常IO・readonly IOの6ケースを保存 | Windows native基準。Wasmの成功を代用しない |
| PHP 8.5.12のRust実行 | [Linux LLVM CI](https://github.com/KANIKAMA-Carcinization/RecastPress/actions/runs/41293870063)で版・固定echo・整数幅8Bを確認 | source `5fd0377`のversion-only実測。例外・Fiber・WP・HTTP・DBは未検証 |
| 言語契約の比較 | [後続CI](https://github.com/KANIKAMA-Carcinization/RecastPress/actions/runs/41295645988)の観測を事後に厳密比較し、基本値・例外は一致、Fiberは不一致 | source `64c004f`。全3ケースの受入は失敗のまま。WP・IOの3ケースは未比較 |
| Windows候補 | 同じWasmのCranelift compileでpanicを記録 | Windows nativeは元の初回正式配備先ではない。Linux成功へ混ぜない |

LinuxのCI証跡は[元commitの入力照合付き](../experiments/php-wasix-host-probe/evidence/linux-llvm-41293870063/provenance.json)で取り込んだ。PHP・LLVMバイナリ、token、期限付き取得URLはGitへ含めない。

言語比較の[生観測と個別比較](../experiments/php-wasix-host-probe/evidence/linux-llvm-41295645988/case-comparison.json)は、成功2ケースだけで候補を合格にしない。Fiberは`FiberError: Cannot resume a fiber that is not suspended`で失敗した。PHPソース側の条件分岐と実際の互換性を調べ、候補採用を保留する。期待値の削減・native PHPへのfallback・P1完了への付替えは行わない。

同じCI環境でcold compileは155,366ms、`run_wasm`内のWASIX/PHP起動・実行・終了は61msだった。純粋なPHP処理時間や製品性能値ではない。コンパイル済みmoduleを再利用し、要求ごとにPHP/WASI状態を新設する実験を次に行う。

## 次の実装

1. 同じコンパイル済みmoduleを3要求で再利用し、要求間の状態分離・回収と時間を観測する。Fiber差分の調査と並行する。
2. WPソースと要求専用領域を有限の能力として渡し、実際の書込み拒否と権限照会の一致を比較する。
3. PHPの公式CGIを最小設定差分でビルドし、要求入口、HTTPの完成後送信、専用RPC、正常・異常終了後の回収をPHP 8.5候補で確認する。ビルド成功だけを要求実行成功にしない。
4. 依存・配布・実版を固定しP0を通過してから、キャッシュなしのWP通常起動と標準wpdb→RustのP1へ進む。

DB・キャッシュの製品経路を先に完成扱いせず、Nodeやnative PHPへの方式変更も行わない。既存のAPI移植件数を増やす開発は再開せず、新構成の実行基盤と互換比較を優先する。
