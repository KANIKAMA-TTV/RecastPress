# 手動の移植・比較レビューを始める

2026-10-29時点の開発用手順。移行診断UI、移植先SDKの配布、Wasmビルド・実行、認証付き管理画面、実サイトの移行は未完成である。以下は利用者または委託先が資料と観測を整理するための入口で、製品による自動診断や公開承認ではない。

公開閲覧からPHPを起動しない方針と、テーマ・functions.phpの移植、テスト結果の確認、公開判断を利用者または委託先が担う役割分担を先に確認する。問い合わせフォームは公開側のPHP実行へつながらない構成が必要になる。RecastPressはAI APIへ接続せず、利用者が自身のAIを操作する。[移植の役割と残る契約](theme-porting.ja.md)。

## 資料を用意する

元テーマ、親子関係、functions.phpと読込み先、依存プラグイン、独自フック、直接SQL、外部通信、フォームなどについて、対象ファイル・由来・版・内容ハッシュと確認状態をローカル資料へ記録する。未知の依存を削除したことにせず、「未確認」として残す。現時点でこの一覧を自動抽出・完全性検査するtoolはない。

AIへ渡すのは利用者が確認したコードと診断用資料に限定する。実DB、パスワードハッシュ、秘密設定、非公開コンテンツは通常の移植資料へ混ぜない。コードにも埋込み秘密があり得るため、この区分だけで除去済みとは扱わない。HTTP記録の本文・query・Locationにも私情報が入り得るので、丸ごとAIへ渡す操作はこの手順に含めない。

[source inventory tool](migration-source-inventory-development.ja.md)では、利用者が選んだ相対file一覧と手動の未確認メモから、長さ・SHAを持つ新規manifestを作れる。sourceは実行・copyせず、自動探索や依存判定もしない。個々の読んだbytesの記録であり、全sourceの同時snapshotや秘密除去の証明ではない。上記の対象一覧の完全性は別途確認する。

## HTTP観測を残す

初回診断時と最終同期後の切替直前に、元サイトの代表ページについてHTTP応答と画面を記録する要件がある。現toolが扱うのは、callerが明示する1URLのHTTP応答だけである。URL自動抽出、画面取得、ログイン状態、JavaScriptの動作、フォーム送信は別途未確認として残す。

[capture tool](http-baseline-development.ja.md)は、対象と保存先を選んでから実行する。新規dirに保存し、前回の記録は上書きしない。3xxは転送先を追わず、4xx／5xxも観測結果として残す。2回の記録だけで同期完了・全URL網羅・移行成功を判断しない。

保存した2つの記録には[オフライン構造比較](http-baseline-comparison-development.ja.md)を使える。有効な入力同士なら差があってもexit 0で、本文・status・選択header・URL等の独立した一致情報を返す。URL、本文、header値をreportへ転記せず、日時を一致判定に含めない。画面・動作・意味の比較は別途必要で、全項目trueも公開承認ではない。

## 移植を依頼するプロンプトのひな形

次の本文に、確認した元資料・対象範囲・対応API資料・未確認一覧を添える。現時点ではSDKとWasm実行契約が未完成なので、存在しないAPIや実行済み成果物を仮定した実装指示にしない。

> 添付した元コード、親子テーマの読込み順、フックと依存一覧を確認し、移植対象の役割と呼出し関係を整理してください。利用可能なRecastPress APIは、添付した版の資料に実在するものだけを使ってください。資料にないAPI・Wasm契約・認証入口は補って実装せず、不足契約と元コードの位置を記録してください。独自機能、直接SQL、外部通信、フォームを黙って削除しないでください。公開閲覧から直接・間接にPHP、ビルド、管理ジョブを起動しない構成を守ってください。各変更を元コードと対応付け、依存とライセンス、未対応、再検証が必要な範囲を提出してください。コンパイルできることを元サイトとの同等性や公開承認に読み替えないでください。

## 比較テストを依頼するプロンプトのひな形

期待結果は元サイトの資料と観測から作り、移植後の実装から逆算しない。実行できない項目も報告へ残す。

> 元サイトの記録と明示した対象範囲を使い、表示・HTTP・操作・保存後の反映を検証する手順を作成してください。各項目に期待結果の出典、入力と前提、実行手順、実測結果、差分、未確認を記録してください。HTTPのstatus、選択header、本文のbyte差と、画面・HTML・JavaScript・フォームの意味の差を区別してください。取得時刻やURLが異なる記録を、同一時点の完全なsnapshotと扱わないでください。比較不能・ビルド不能・実行不能を成功へ変換せず、不一致の再現方法を示してください。テスト通過から全機能の同等性、移行成功、公開承認を宣言しないでください。

このひな形はサイト別に生成・実行した実績ではない。資料の欠落、代表URLと操作の選定、画面取得、SDK／Wasm環境、同期・切替・復旧の残件は、利用者が判断できる形でレビュー記録へ残す。
