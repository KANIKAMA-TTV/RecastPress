# WP本体の標準仕様へ統一する方針

決定日：2026-10-25（日本時間）。ユーザー指定：「WP本体の標準仕様で一貫して」。D10-10・R31。設計方針の決定であり、ソース照合・実装・試験は未完了。

## 1. 今後の判断基準

互換基準WordPress 7.1.3のコア標準機能・設定・APIの振る舞いをRecastPressの基本仕様とする。既決の差分を除き、標準機能の採否・初期値・条件を一つずつ選び直さず、基準ソースから仕様と比較試験へ起こす。これまで未決だった標準機能は「コアに含まれるかを照合し、標準なら採用対象」と扱う。標準であることを確認せず外部プラグインや独自機能まで含めない。

コメント更新フィードはこの方針により初回対応を決定した（D10-09・R32）。RSS 2.0・Atomのサイト全体・記事ごとのフィードをRustで提供し、標準リンク・購読URL・本文と件数・更新・公開状態を基準WPと比較する。一般投稿者への返信購読メールや外部スパムサービスを、このフィードの決定だけで追加しない。

公開REST、トラックバック・ピンバック、標準フォーム・編集操作等も、基準コアの一覧で仕様を確認して互換契約へ取り込む。標準機能を理由なく初回から除外しない。既決の制約と衝突する項目は差分表へ載せ、実現方式か明示的な差分の判断を一件ずつ扱う。安全な実行方式・外部副作用の権限まで、標準仕様を理由に無制限に許可しない。

## 2. 維持する既決事項

| 項目 | 今回の方針との関係 |
| --- | --- |
| 互換基準 | 7.1.3固定。最新版へ自動追随しない。固定アーカイブの取得・checksum照合は完了。部分実装・個別比較があり、全API／製品互換は未達 |
| 初回サイト構成 | 単一サイト先行。マルチサイト後続という明示決定を維持 |
| コメントの初期受付 | 新規RecastPressサイトでは無効。元WPの受付・承認設定は移行時に引き継ぐ |
| 実装・実行 | Rustが本番コア。公開起点の処理は非同期も含めPHPへ到達させない。移植テーマ等はサーバー側Wasmで実行 |
| 公開・管理のプロセス | 後続のD05・R33でRustの公開系と管理系を別プロセスと決定。具体的なホスト・コンテナ・内部通信は詳細化 |
| 管理系への接続 | 後続のD06-01・R34でHTTPS＋認証・認可によりインターネットから利用、VPN制限は任意と決定。認証の詳細は個別設計 |
| SSOの追加提供 | ユーザー指定によりD06-03・R35で全ユーザー向けの標準機能、初期offと決定。後続のR36・R37によりMFA非実装・OIDC限定と決定 |
| SSOの方針と移行例外 | R38でオフ／ユーザー任意／必須要求の3段階、初期off。R39で必須時の既存ユーザーのパスワードログインを一度だけ許可。利用範囲等は詳細化 |
| 独自キャッシュ・設定 | R42でオンメモリ・GETクエリー・TTLなし・全パージ、R43で追加1画面、R49で監視不成立時停止、R50で初期オン、R51で移行時質問、R52で容量完全自動・手動上限なしを採用 |
| AIの役割 | テーマ・functions.phpのRust移植は利用者自身のAIで実施。製品はAI APIへ接続しない |
| プラグイン互換 | 任意の第三者プラグインの無条件互換を意味しない。PHPは認可済み管理・内部処理に限定 |
| 本体更新 | R40で本体のみ自動更新。他は操作説明・セットアップ支援で更新実行コードなし。R56でセキュリティ更新の配信終了版を強く警告。R57でスキーマ変更なしのRust全体の一時二重起動・切替を採用し、無停止は保証しない |
| 配備・DB・ライセンス | 既決の三環境、MariaDB・MySQL両対応、GPLv2互換維持を変更しない。R58で編集用正本のWP互換構造維持と独自状態・公開用データの分離を採用。直接SQL許可は別判断 |

本方針を理由に過去の明示決定を取り消さない。新たな非互換、追加制限、後続対応への変更が必要なら、理由・影響・代替案を具体化して協議する。

## 3. 仕様化と検証

コア標準項目を、採用対象、固定ソース照合済み、実装済み、比較試験済みに分けて管理する。「仕様はWP準拠」と書いただけで実装・互換検証済みにはしない。[互換基準](wp-compatibility.ja.md)のAPI台帳へ基準版・ソース位置・設定と初期値・権限・入力／出力・状態遷移・副作用・適用条件・試験結果を記録する。

コア仕様で決まる細部は再質問せず仕様抽出を進める。新たな製品上の選択は、プロセス配置、配備・永続化、SMTP等の送信手段、認証基盤、移行停止時間、復旧目標、比較検証に使うサイト群等である。編集の標準動作と、Gutenbergのコードを再利用するか等の実装手段は区別する。

管理・SSOの既決事項は[認証設計](authentication.ja.md)、キャッシュは[キャッシュ設計](cache-and-settings.ja.md)、更新のR40・R56・R57は[本体更新設計](automatic-updates.ja.md)を正本とする。スキーマ変更なしの切替方式は採用済みであり、残る更新設定やスキーマ変更ありの方式まで決定済みとはしない。全残件と次回の推奨議題は[未決一覧](decisions.ja.md)と[引継ぎ](handoff.ja.md)へ整理した。
