# RecastPress 基本設計レビュー

評価段階：設計レビュー。実装、侵入試験、性能測定、配備試験は未実施。

この文書は記録日時点の評価。後続のD25〜D29で初回公式配備先はLinux Docker Compose・Railway・AWS Lightsailの三環境に変更し、自動更新はRecastPress本体のみに限定した。配備先・更新範囲の現在地は[判断記録](decisions.ja.md)と[詳細設計](design.ja.md)を参照する。

## 1. 総合評価

公開リクエストからPHPを起動しない境界、公開用と編集用のデータ・権限の分離、検証済みの不変な公開世代への切替、Wasmホストの能力制限は、攻撃面と障害の波及を抑えるための整合した設計案である。一方、管理系、PHPプラグイン、利用者が持ち込むRustソースと依存、Wasmホストは引き続き重要な信頼境界となる。PHPを公開経路から外すだけで、製品全体の安全性を証明したとは言えない。

現時点で最も大きい製品上のリスクは、初回リリースに求める互換範囲と正式対応環境の広さに対し、合格条件、対象サイト像、運用上の数値目標が未確定なことである。安全性・互換性・運用可能性は、実装後の代表シナリオと環境別試験で評価する必要がある。本レビューの優先度は**設計上の対応順**であり、実在する脆弱性の重大度を判定したものではない。

## 2. 判断に使った外部状況

- [Verizon 2026 DBIRの公表資料](https://www.verizon.com/about/news/breach-industry-wide-dbir-finds)では、調査対象の侵害でソフトウェア脆弱性の悪用が主要な侵入口となり、第三者が関与する侵害の割合も増加したと報告されている。これはRecastPress固有の侵害確率ではなく、更新速度と依存管理を重視する根拠である。
- [OWASP Top 10:2025](https://top10.owasp.org/2025/fa/)は、アクセス制御不備、設定ミス、ソフトウェア供給網の失敗を主要なリスクに挙げる。PHPの有無だけではこれらを解消できない。
- [WordPress 7.1.3のリリース情報](https://wordpress.org/documentation/wordpress-version/version-7.1.3/)によれば、この互換基準版自体が七件のセキュリティ修正を含む。基準版の固定と、以後の脆弱性修正を取り込む運用は別々に設計する必要がある。
- [Cloud Runの実行契約](https://docs.cloud.google.com/run/docs/container-contract)は、ローカルファイルが永続しないこと、インスタンスの増減・停止があることを明示する。クラウド対応には、外部永続化だけでなく、ジョブ再開、権限、起動時間、復旧の検証が必要である。
- WordPressの[REST API](https://developer.wordpress.org/rest-api/)はブロックエディターの基盤でもある。編集UIを再利用する判断と、公開・管理APIの互換範囲は切り離して決めにくい。

## 3. 評価できる点

1. [公開サービスの権限案](design.ja.md)では、PHP起動権限、ジョブ投入権限、編集DB書込み資格情報を公開サービスへ渡さない。URLだけに頼らず、PHP実行直前に操作権限を検査する方針も妥当である。
2. [保存から公開までの状態遷移](design.ja.md)は、編集改訂と処理要求の原子的記録、ジョブの再実行、公開世代の切替、失敗時の既存公開状態の維持を考慮している。
3. [Wasm成果物契約](theme-module-contract.ja.md)は、公開用と管理用の能力を分け、禁止import、資源上限、要求間の状態分離、ビルド時に実行されるコードの隔離を検証対象にしている。
4. [互換基準の管理](wp-compatibility.ja.md)は、未対応APIを空実装で対応済みにしない方針を示す。テーマ移植の成功をビルド成功だけで認定しない点も適切である。
5. [バックアップ・更新案](design.ja.md)には、復元試験と不可逆スキーマ変更への注意がある。運用上の失敗を設計段階から扱っている。

## 4. 優先して見直す事項

| 優先度 | 論点 | 現状とリスク | 次の設計成果物 |
| --- | --- | --- | --- |
| 最優先 | 初回の互換範囲と合格条件 | 標準テーマ用API全体、任意テーマの移植、PHPプラグイン、MariaDB・MySQL、六つの配備構成を初回の対象にしている。一方、対象テーマ・プラグイン・利用操作、API母集合、性能目標は未決。広い目標を検証済みの互換性と誤認させる恐れがある。 | 代表サイト群、プラグイン・テーマの版と操作、機能別の対応表、初回リリースの合否基準。製品目標と検証済み範囲を別表示する。 |
| 最優先 | 管理系の信頼境界 | 公開／管理サービスの配置、管理UIの公開範囲、MFA・SSO、権限回復が未決。管理者の認証突破はPHP処理と公開切替に及び得る。 | 公開・管理・ワーカー・PHPの脅威モデル、役割別権限表、認証・セッション・監査の標準設定。検証には[OWASP ASVS 5.0](https://asvs.owasp.org/)を対応付ける。 |
| 高 | 持込みコードと供給網 | 隔離ビルドとハッシュ記録は提案済み。ただし、ハッシュは内容の同一性を示しても安全性を保証しない。依存やWasmエンジンの新たな脆弱性、悪意あるビルド依存への継続対応が必要。 | 依存・成果物の一覧と由来、ビルド証跡、検証可能な署名、脆弱性監視、停止・差替え・通知の手順。参考：[NIST SSDF](https://csrc.nist.gov/pubs/sp/800/218/final)、[SLSA Provenance](https://slsa.dev/spec/v1.2/provenance)。 |
| 高 | WasmとPHPの権限逸脱・可用性 | 公開Wasmに管理APIを渡さない案は良い。ホストAPIの欠陥、過大なDB呼出し、出力HTMLによるXSS、PHPプラグインの内部API濫用は残る。Wasmの隔離をアプリケーション全体の隔離と同一視できない。 | 能力別APIの拒否試験、ホスト側の時間・件数・出力上限、HTMLの出力文脈別検証、PHP処理のネットワーク・ファイル権限と監査。参考：[Wasmtime Security](https://docs.wasmtime.dev/security.html)。 |
| 高 | 非公開化・削除の即時性 | 不変の公開世代は復旧に有利だが、古いコンテンツのCDN残留時間は未仕様。機密情報の誤公開時に旧世代への差戻しやバックアップからの再露出も問題となる。 | 緊急撤回の最大許容時間、キャッシュ失効、世代保持・削除・復元時の再公開条件を定めた試験。 |
| 高 | 当時の六構成の安全な標準配備 | 各環境の配置は提案段階。サービスID、最小権限、秘密更新、内部通信、障害復旧に環境差がある。構成名だけでは正式対応を証明できない。 | 環境別の配備構成、権限表、更新・バックアップ・別環境復旧の試験結果。[Cloud RunのサービスID指針](https://docs.cloud.google.com/run/docs/securing/service-identity)も参照する。 |
| 中 | 編集体験と公開機能 | Gutenberg再利用、公開REST、検索、コメント、フォームの範囲が未決。これらの依存を持つテーマは見た目だけ一致しても移行できない。 | 初回の利用者操作一覧、編集方式と必要なREST API、機能ごとの「対応／代替／移行不可」判定。 |

各論点の現在地は[設計判断・確認事項](decisions.ja.md)のD02〜D14、[詳細設計](design.ja.md)第4〜12章、[Wasm成果物契約](theme-module-contract.ja.md)第5〜8章に対応する。とくに削除・非公開化後のキャッシュ、外部副作用、移行時の認証情報、RPO/RTOは運用要件として数値化する必要がある。

## 5. 推奨する判断順と判定基準

1. **対象サイト像と初回合格条件**：移行元の種類、テーマ・プラグインの版、公開・編集操作を固定し、未検証を成功に数えない。
2. **管理系の安全な標準構成**：公開／管理の配置、管理認証、PHPジョブの起因と権限、監査・緊急停止を定める。
3. **成果物の受入れと更新**：隔離ビルドに加え、依存の追跡、脆弱性修正の反映期限、成果物の差替え・撤回を定める。互換基準7.1.3を固定しても、新たな脆弱性情報への対応を止めない。
4. **公開状態の安全性**：非公開化・削除、世代切替、CDN失効、復元後の再公開を一つの契約として試験する。
5. **配備先ごとの実証**：当時の六構成で導入、移行、更新、障害、復旧、秘密更新、負荷と費用を確認する。数値目標が未決なら性能・運用達成を宣言しない。

採用判断では、現行WordPressを更新し、権限分離・管理認証・監視を強化した運用構成も比較対象に置くのが中立的である。RecastPressの価値は、公開PHPの排除と移行・公開の制御が、追加する互換層と実行基盤の保守負担を上回るかで評価する。

## 6. レビューの限界

この文書は設計資料のレビューであり、実装上の脆弱性の発見や不存在を示すものではない。外部の侵害統計は一般的な脅威動向であり、RecastPressの被害確率を直接示さない。クラウド製品の仕様、脅威情報、WordPressの修正情報は変わり得るため、詳細設計とリリース判定の時点で公式資料を再確認する。
