# 想定ユーザー・対象サイトと合格条件の具体化

更新日：2026-10-25（日本時間）。D21・R45のユーザー指定を記録。用途の対象像と単一サイトの月間20万PVまでの想定を決定。性能・費用の数値目標、代表テーマ等の選定・試験は未完了。

## 1. 決定した対象像

CDNを使うまでもないアクセス規模のサイトを主対象とし、CDNを必須にせず運用できる設計とする。具体的には大企業ではないカンパニーサイト、商品紹介、カタログ、ブランディング、大規模なキャンペーンを打たないLP、アマチュアのサイトを想定する。

**規模の想定（2026-10-25）**：単一サイトあたり月間20万PVまでを主対象とする。PVはページ閲覧数であり、訪問者数、HTTPリクエスト数、転送量、ピーク時の同時接続数を表さない。この数値は設計対象の目安であり、現時点で処理能力や応答時間を保証する測定結果ではない。

瞬間的なアクセス集中への対応は配備先の計算資源・ネットワーク・負荷分散・CDN等のインフラ構成に大きく依存する。RecastPress単体で突発的な集中アクセスを吸収する機能や、ピーク処理能力の保証を製品目標にしない。製品側の負荷対策は既決のオンメモリキャッシュまでとし、追加の分散キャッシュや自動スケーリング等を標準機能として要求しない。必要な集中アクセス対応は配備構成で検討する。

大企業向けの大規模運用や大規模キャンペーン時の負荷を、標準構成の設計・合格条件の中心には置かない。CDNの利用を禁止する指定ではなく、任意導入時は外部キャッシュの失効等を別に契約化する。初回の三つの公式配備環境、単一サイト先行、WP本体標準仕様、任意テーマのRust移植を目標とする既決事項は変更しない。

ユーザーの「WordPressユーザーの大半が該当すると考えている」は市場仮説として記録する。調査済みの市場比率・利用者割合を示す事実や性能上限には置き換えない。市場規模の定量検証は未実施。

**利用・提供の前提（2026-10-25）**：移行は、製品が提示する具体的な手順とAI向けプロンプトに沿って作業できる運用者、または利用者から委託された担当者が行う。functions.phpを自力でカスタムできる開発者も移行作業の担い手として想定する。テーマ・functions.phpの移植、テスト結果の確認、公開判断は利用者または委託先の責任。利用者全員への個別支援や制作者による受託を前提にせず、個別サポートのないOSSパッケージとして提供する。RecastPressの診断・テスト支援はサイト移行成功や全機能同等性を保証しない。手順に沿って実施可能か、必要な技能と作業量は実証前の仮説として検証する。

**問い合わせフォーム方針（2026-10-26更新、D23・D23-01）**：問い合わせフォームをCMS本体から切り離し、WordPress内へ統合する構成を非推奨とする。フォームのメールサーバー接続と問い合わせデータ保持に伴うリスクを、この方針の理由として扱う。RecastPressの移行診断では既存フォームと公開時PHP依存を検出し、移行後もそのまま動作すると表示せず、分離と置換を案内する。Tallyを第一推奨、独自デザインを維持する場合はWeb3Formsを代替候補とし、プラグイン不要のリンク・埋込み・外部送信手順を用意する。本体は受付の中継・フォーム用SMTP・配送・問い合わせデータ保管を持たず、契約・設定・データ管理は利用者が担う。既存データの移行・廃止手順は未決。[外部フォーム推奨](external-forms.ja.md)を参照。

コメント受付と通知はWP標準機能の移行用として提供し、通常利用を推奨しない。新規サイトの受付初期offを維持し、元WPで明示された設定は引き継ぐ。外部メールサーバーへの接続・配信成功は保証せず、送信失敗は運用者に分かるようにする。

## 2. 代表サイトと利用シナリオの案

以下は対象像を比較検証用シナリオへ起こす案であり、具体的なサイト・テーマ・プラグイン名やデータ量の採用ではない。

| 対象 | 代表的な内容・操作の案 |
| --- | --- |
| カンパニーサイト | 会社案内、事業・サービス、ニュース、固定ページ更新、画像差替え、URL維持と移行 |
| 商品紹介・カタログ | 商品紹介ページ、分類・一覧・検索・ページ送り、GETクエリーによる絞込み、画像・資料更新 |
| ブランディング | テーマの表示・画像・資産・メニュー、移植後の表示比較と更新追従 |
| 通常規模のLP | 公開・改訂・差替え、計測等のGETクエリー変種、キャッシュと更新反映。大規模広告集中は基本負荷に含めない |
| 個人・趣味等のアマチュアサイト | 投稿・固定ページ・画像、検索・フィード、必要に応じたコメント、少人数での管理と継続更新 |

商品紹介・カタログの想定から決済・在庫・会員機能を一括採用しない。問い合わせフォームは上記の分離方針に従い、それ以外の独自プラグインも用途名だけで互換としない。公開起点のPHP禁止を維持し、対応・分離・代替・移行不可を利用機能ごとに診断する。代表群は対象像を検証するためのもので、製品目標をそのテーマだけへ縮小する理由にはしない。

## 3. 設計へ反映する方向

CDNなしでの直接配信を基本の検証経路とし、Rustによる公開配信とオンメモリキャッシュを用いる。複数の専用基盤や分散キャッシュ製品を、アクセス規模の想定だけを理由に必須化しない。月間20万PVという総量から瞬間最大負荷を逆算せず、実際のプロセス構成は既決の公開・管理分離を守って各配備アダプターで具体化する。

管理者が少人数でも設定・更新・バックアップ・復旧を扱えるよう、独自設定の追加1画面、RecastPress本体の自動更新と環境更新の手順案内、診断と処理状態の表示を具体化する。必要な運用手順・費用・停止条件を明らかにする。安価・低負荷・簡単さの達成は測定・操作試験で判断し、対象像だけで達成済みとはしない。

AIコーディングを前提とし、実装量の多さだけを対応先削減の理由にしない。必要性が薄い、または実装・検証・継続保守の負荷が高い配備先や機能は、対象ユーザーへの価値に照らして個別に絞り込みを検討する。三環境の初回正式対応等の既決事項を、この検討だけで変更しない。

キャッシュが十分温まる前の少ないアクセス、初回・再起動後・全パージ直後のミス、GETクエリーによるキー増加と容量圧迫を基本シナリオに含める。キャッシュヒット時だけで応答性能を合格にせず、原本・公開世代からの通常配信と更新反映も測る。低頻度アクセスでもTTLなし保持と変更検知・全パージの整合性を検証する。

CDNを基本経路に置かないため、まず本体とブラウザーのHTTPキャッシュ、公開世代とオンメモリの失効を具体化する。CDN導入が前提の構成や数字を基本合格条件へ混ぜない。既存の公開権限、SSO、更新・バックアップ／復旧等の要件は対象規模を理由に解除しない。

## 4. 残る数値と検証

月間20万PVまでの想定は決定済み。日間アクセスの偏り、通常時の要求数・同時数、ページ・画像・資料のサイズ、投稿・商品紹介・メディア件数、編集者数と更新頻度、許容応答時間、利用者の地域と回線、月額予算、停止時間、RPO/RTO・保持期間はD14で具体化する。突発的な集中アクセスの数値目標はRecastPress単体の合格条件に置かず、必要な場合は対象インフラを含む別の運用条件として定める。

D03で代表テーマ・プラグインと版、データ量・操作・比較条件を選定する。T38でCDNなしの対象シナリオを、通常・コールド・全パージ後・クエリー増加・更新競合等に分けて三環境で検証し、応答時間・メモリ・CPU・DB負荷・転送量・費用・運用操作を記録する。月間20万PVの想定と、D14で別途合意する通常運用条件を用いて合否を判断する。実装・負荷試験・市場調査は未実施。
